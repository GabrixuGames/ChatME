{\bfseries{Accessible?}} Yes. Labeling, aria attributes, and DOM ordering tested with Voice Over and Chrome Dev\+Tools. Dialog composes an accessible Dialog implementation.

{\bfseries{Virtualization?}} No. Good performance up to 2,000-\/3,000 items, though. Read below to bring your own.

{\bfseries{Filter/sort items manually?}} Yes. Pass {\ttfamily should\+Filter=\{false\}} to Command. Better memory usage and performance. Bring your own virtualization this way.

{\bfseries{React 18 safe?}} Yes, required. Uses React 18 hooks like {\ttfamily use\+Id} and {\ttfamily use\+Sync\+External\+Store}.

{\bfseries{Unstyled?}} Yes, use the listed CSS selectors.

{\bfseries{Hydration mismatch?}} No, likely a bug in your code. Ensure the {\ttfamily open} prop to {\ttfamily Command.\+Dialog} is {\ttfamily false} on the server.

{\bfseries{React strict mode safe?}} Yes. Open an issue if you notice an issue.

{\bfseries{Weird/wrong behavior?}} Make sure your {\ttfamily Command.\+Item} has a {\ttfamily key} and unique {\ttfamily value}.

{\bfseries{Concurrent mode safe?}} Maybe, but concurrent mode is not yet real. Uses risky approaches like manual DOM ordering.

{\bfseries{React server component?}} No, it\textquotesingle{}s a client component.

{\bfseries{Listen for ⌘K automatically?}} No, do it yourself to have full control over keybind context.

{\bfseries{React Native?}} No, and no plans to support it.
