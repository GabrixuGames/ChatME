\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2898}{}\doxysubsubsection{\texorpdfstring{{\ttfamily constructor} equality now required}{{\ttfamily constructor} equality now required}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2898}
To align with other implementations common in the community, but also to be more functionally correct, the two objects being compared now must have equal {\ttfamily constructor}s.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2899}{}\doxysubsubsection{\texorpdfstring{{\ttfamily Map} / {\ttfamily Set} comparisons no longer support IE11}{{\ttfamily Map} / {\ttfamily Set} comparisons no longer support IE11}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2899}
In previous verisons, {\ttfamily .for\+Each()} was used to ensure that support for {\ttfamily Symbol} was not required, as IE11 did not have {\ttfamily Symbol} and therefore both {\ttfamily Map} and {\ttfamily Set} did not have iterator-\/based methods such as {\ttfamily .values()} or {\ttfamily .entries()}. Since IE11 is no longer a supported browser, and support for those methods is present in all browsers and Node for quite a while, the comparison has moved to use these methods. This results in a \texorpdfstring{$\sim$}{\string~}20\% performance increase.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2900}{}\doxysubsubsection{\texorpdfstring{{\ttfamily create\+Custom\+Equal} contract has changed}{{\ttfamily create\+Custom\+Equal} contract has changed}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2900}
To better facilitate strict comparisons, but also to allow for {\ttfamily meta} use separate from caching, the contract for {\ttfamily create\+Custom\+Equal} has changed. See the \href{./README.md\#createcustomequal}{\texttt{README documentation}} for more details, but froma high-\/level\+:


\begin{DoxyItemize}
\item {\ttfamily meta} is no longer passed through to equality comparators, but rather a general {\ttfamily state} object which contains {\ttfamily meta}
\item {\ttfamily cache} now also lives on the {\ttfamily state} object, which allows for use of the {\ttfamily meta} property separate from but in parallel with the circular cache
\item {\ttfamily equals} is now on {\ttfamily state}, which prevents the need to pass through the separate {\ttfamily is\+Equal} method for the equality comparator
\end{DoxyItemize}\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2901}{}\doxysubsubsection{\texorpdfstring{{\ttfamily create\+Custom\+Circular\+Equal} has been removed}{{\ttfamily create\+Custom\+Circular\+Equal} has been removed}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2901}
You can create a custom circular equality comparator through {\ttfamily create\+Custom\+Equal} now by providing {\ttfamily circular\+: true} to the options.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2902}{}\doxysubsubsection{\texorpdfstring{Custom {\ttfamily meta} values are no longer passed at callsite}{Custom {\ttfamily meta} values are no longer passed at callsite}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2902}
To use {\ttfamily meta} properties for comparisons, they must be returned in a {\ttfamily create\+State} method.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2903}{}\doxysubsubsection{\texorpdfstring{Deep links have changed}{Deep links have changed}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2903}
If you were deep-\/linking into a specific asset type (ESM / CJS / UMD), they have changed location.

{\bfseries{NOTE}}\+: You may no longer need to deep-\/link, as the build resolution has improved.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2904}{}\doxysubsection{\texorpdfstring{Enhancements}{Enhancements}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2904}
\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2905}{}\doxysubsubsection{\texorpdfstring{New "{}strict"{} comparators available}{New "{}strict"{} comparators available}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2905}
The following new comparators are available\+:


\begin{DoxyItemize}
\item {\ttfamily strict\+Deep\+Equal}
\item {\ttfamily strict\+Shallow\+Equal}
\item {\ttfamily strict\+Circular\+Deep\+Equal}
\item {\ttfamily strict\+Circular\+Shallow\+Equal}
\end{DoxyItemize}

This will perform the same comparisons as their non-\/strict counterparts, but will verify additional properties (non-\/enumerable properties on objects, keyed objects on {\ttfamily Array} / {\ttfamily Map} / {\ttfamily Set}) and that the descriptors for the properties align.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2906}{}\doxysubsubsection{\texorpdfstring{{\ttfamily Typed\+Array} support}{{\ttfamily Typed\+Array} support}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2906}
Support for comparing all typed array values is now supported, and you can provide a custom comparator via the new {\ttfamily are\+Typed\+Arrays\+Equal} option in the {\ttfamily create\+Custom\+Equal} configuration.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2907}{}\doxysubsubsection{\texorpdfstring{Better build system resolution}{Better build system resolution}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2907}
The library now leverages the {\ttfamily exports} property in the {\ttfamily package.\+json} to provide builds specific to your method of consumption (ESM / Common\+JS / UMD). There is still a minified UMD version available if you want to use it instead.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2908}{}\doxysubsubsection{\texorpdfstring{{\ttfamily are\+Primitive\+Wrappers\+Equal} option added to {\ttfamily create\+Custom\+Equal} configuration}{{\ttfamily are\+Primitive\+Wrappers\+Equal} option added to {\ttfamily create\+Custom\+Equal} configuration}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2908}

In previous versions, there were automatic fallbacks for certain ES2015 features if they did not exist\+:


\begin{DoxyItemize}

There is still an option if you require support for these legacy environments, however; see \href{./README.md\#createcustomequal}{\texttt{{\ttfamily create\+Custom\+Equal}}} and \href{./README.md\#createcustomcircularequal}{\texttt{{\ttfamily create\+Custom\+Circular\+Equal}}} for more details.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2915}{}\doxysubsubsection{\texorpdfstring{{\ttfamily create\+Custom\+Equal} contract has changed}{{\ttfamily create\+Custom\+Equal} contract has changed}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2915}

See \href{./README.md\#createcustomequal}{\texttt{the documentation}} for more details.\hypertarget{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2916}{}\doxysubsection{\texorpdfstring{Enhancements}{Enhancements}}\label{md_frontend_2node__modules_2fast-equals_2_c_h_a_n_g_e_l_o_g_autotoc_md2916}
